# 경기 보상과 성장

설정: `config/rewards.json`. 변경 후 서버 재시작이 필요합니다.

## 기본 보상

정상 종료한 참가자에게 개인 참여 시간을 기준으로 지급합니다. 시간은 분 단위 내림이며 최대 30분까지 반영합니다.

| 항목 | XP | 포인트 |
|---|---:|---:|
| 경기 완료 | 100 | 200 |
| 참여 1분 | 30 | 60 |
| 승리 / PvE 클리어 추가 | 300 | 600 |
| 무승부 추가 | 150 | 300 |
| PvP 킬, 최대 50킬 | 10 | 10 |
| PvE 킬, 최대 100킬 | 1 | 2 |

패배/PvE 실패에도 완료·시간·킬 보상은 지급합니다. 솔로 PvE는 합계의 75%를 내림하여 지급합니다. 한 경기 개인 상한은 3,000 XP와 6,000 포인트입니다. 캐시·쿠폰·아이템은 지급하지 않습니다.

| 10분 경기 예시 | XP | 포인트 |
|---|---:|---:|
| PvP 10킬 승리 | 800 | 1,500 |
| PvP 10킬 패배 | 500 | 900 |
| 다인 PvE 100킬 클리어 | 800 | 1,600 |
| 다인 PvE 1,000킬 클리어 | 800 | 1,600 |
| 솔로 PvE 100킬 클리어 | 600 | 1,200 |

개인 참여 60초 미만, 중도 이탈, 훈련 옵션, 상대 팀이 없는 PvP는 보상과 전적 증가가 없습니다. 방 이탈로 기존 게임이 강제 중단되는 경로는 전원 보상 없이 종료합니다. PvP는 30점 또는 방 제한시간 도달 시 종료합니다. PvE는 마지막 라운드 클리어/실패 시 한 번 정산합니다.

## 성장과 저장

- 계정 최대 레벨 100, 기체 최대 레벨 30. 누적 XP는 최대 레벨 이후에도 저장됩니다.
- 레벨 L에서 다음 레벨까지 필요한 XP: `1,000 + 250 × (L - 1)`.
- 계정 경험치·승패·무승부·킬·데스와 포인트를 저장합니다.
- 기체 경험치·킬·데스·출격 수는 경기 시작 시 선택한 기체에 합산합니다. 경기 중 기체별 사용량 분배는 아직 지원하지 않습니다.
- 기록용 킬/데스는 개인당 경기당 최대 500입니다. PvE 보상용 킬 상한 100과 별도입니다.
- `match_rewards`의 경기 UUID와 계정 ID 복합키로 중복 지급을 막습니다. 계정·전적·기체·지급 이력은 단일 DB 트랜잭션입니다.
- 포인트 잔액 상한은 2,147,483,647이며 결과창에는 실제 추가된 포인트를 전송합니다.

## 설치 및 장애 복구

처음 설치할 때 서버 폴더에서 `npm run rewards:migrate`를 실행한 뒤 서버를 시작합니다. 기존 데이터는 지우지 않고 지급 이력 테이블을 추가합니다. 이번 로컬 설치에는 이미 적용했습니다.

종료 시 `private-state/pending-rewards`에 정산 파일을 먼저 기록합니다. DB 저장 실패 시 파일을 유지하고 다음 서버 시작 때 재처리합니다. 이 폴더는 서버의 개인 상태이므로 GitHub/클라이언트에 배포하지 말고 DB와 함께 백업하십시오. 진행 중 서버가 강제 종료되어 아직 정산 파일이 없는 경기는 복구하지 않습니다.

## 확인 범위와 한계

자동 테스트와 임시 계정을 사용한 실제 MySQL 저장·중복 정산 검사를 통과했습니다. 기존 클라이언트 DLL의 결과 수신 구조를 오프라인 분석하여 패킷을 구성했습니다. 실제 게임에서 승리/패배 결과창과 재접속 후 증가한 수치는 운영자가 서버를 재시작한 뒤 확인해야 합니다.

금액은 서버가 계산하지만 전투 이벤트는 방장 클라이언트가 보고하는 기존 구조입니다. 비방장 결과 보고와 일부 중복 이벤트를 거부하며, 완전한 부정행위 검증이나 AFK 탐지는 구현하지 않았습니다. PvE 고난도/보스별 가산점도 현재 없습니다.

## 참고

[Valve의 공식 CS:GO 경험치 설명](https://www.counter-strike.net/operationbloodhound/givethisaread)의 모드별 승리/점수 기반 설계를 참고했습니다. 본 서버의 수치는 자체 설정이며 다른 게임의 수치를 그대로 복제하지 않았습니다. PvE는 킬 수가 급증하는 특성을 고려하여 완료·시간 중심으로 정하고 킬 보상에 별도 상한을 두었습니다.
