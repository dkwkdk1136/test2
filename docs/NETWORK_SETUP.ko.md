# 외부 참가자와 플레이하기

## 확인한 구조와 증상의 의미

이 코드는 로그인/로비를 처리하는 Node 서버와 실제 전투를 여는 방장 게임 클라이언트를 구분합니다.
Node 서버는 TCP 9211과 TCP 30907에서 접속을 받고, 전투를 시작하면 방장의 `Ready_Host_CA` 응답에 담긴 포트를 다른 참가자에게 전달합니다.
`30907`이라는 이름이 GameServer라고 해서 실제 전투 접속 포트도 반드시 30907인 것은 아닙니다.

기존에는 서버가 관찰한 방장의 접속 IP를 그대로 참가자에게 전달했습니다.
방장이 같은 PC에서 `127.0.0.1`로 로그인하면 외부 참가자에게도 `127.0.0.1`이 전달될 수 있습니다.
외부 참가자 입장에서 그 주소는 자기 자신의 PC이므로 방장에게 연결되지 않습니다.
방장이 내부 IP로 접속했거나 공유기가 전투 포트를 차단하는 경우도 외부 접속은 실패할 수 있습니다.

PVE와 PVP에서 방장은 남아 있고 초대한 사람만 로딩 후 로비로 돌아가는 증상은 이 문제와 부합합니다.
다만 당시 로그와 실제 두 PC 사이의 패킷을 확인하지 못했으므로, 이번 장애의 확정 원인이라고 단정하지는 않습니다.
클라이언트/맵 파일 차이, 게임 클라이언트의 연결 제한 시간, 다른 프로토콜 문제도 별도 확인 대상입니다.

## 서버와 방장을 같은 PC / 같은 공인 IP로 사용

서버를 다른 PC로 옮길 필요 없이 다음 설정을 사용할 수 있습니다.

1. 기존 설치라면 `config/server.json`을 백업하고 아래 `gameHosts` 항목을 추가합니다. 기존 `cachePath`, 계정 설정 등은 유지합니다.
2. 새 설치라면 `config/server.internet.example.json`을 `config/server.json`으로 복사한 뒤 모든 예시 값을 실제 값으로 바꿉니다.
3. `YourHostLogin`을 **방장의 로그인 아이디**로 바꿉니다. 게임 안의 닉네임이 아닙니다. 대소문자는 구분하지 않습니다.
4. `publicHost`와 `gameHosts`의 `address`를 각각 설정합니다. 같은 공인 IP를 사용한다면 두 값이 같습니다.
5. Node 서버를 재시작합니다. 설정은 실행 중 자동으로 다시 읽지 않습니다.

```json
{
    "publicHost": "203.0.113.10",
    "cachePath": "C:/Games/MetalRage/Data/System/Cache.Bin",
    "gameHosts": {
        "YourHostLogin": {
            "address": "203.0.113.10"
        }
    }
}
```

`203.0.113.10`은 설명용 주소이며 실제 접속에 사용할 수 없습니다. 실제 공인 IPv4로 교체하세요.
외부 참가자의 게임 실행 배치 파일은 로그인 서버의 실제 IP와 `port=9211`을 사용해야 합니다.
방장은 같은 PC라면 로그인에 `127.0.0.1`을 사용해도 됩니다. 참가자에게 전달되는 전투 주소는 위 설정을 사용합니다.

`gameHosts`가 없으면 종전처럼 서버가 관찰한 방장 주소와 방장이 보고한 포트를 사용합니다.
다만 외부 참가자에게 루프백 주소를 전달해야 하는 상황에서는 시작을 거절하고 이유를 로그에 남깁니다.
잘못된 주소로 로딩을 시작시키는 것을 막기 위한 동작입니다. 이때 설정을 수정하고 재시작하세요.

## 반드시 확인할 포트와 방화벽

| 용도 | 목적지 | 포트 |
| --- | --- | --- |
| 로그인/디스패치 | Node 서버 PC | TCP 9211 |
| 로비/방 제어 | Node 서버 PC | TCP 30907 |
| 실제 전투 | 방장 게임 PC | `host-ready` 로그의 `reportedPort` |

원본 [서버 설치 안내](https://github.com/shanzenos/MRO-Server/wiki/Server-Setup-Tutorial)는 9211과 30907에 TCP/UDP 포워딩을 안내합니다.
현재 JavaScript 서버의 리스너는 TCP입니다. 전투는 방장 게임 프로세스가 열므로, 로비 서버 포트만 열려 있는지 확인해서는 충분하지 않습니다.
게임 실행 중 `netstat -ano`로 방장 프로세스가 실제 사용하는 포트와 프로토콜을 확인하고 해당 인바운드 통신을 허용하세요.
공유기 설정에서 TCP/UDP를 함께 지정하는 방식이라면 실제 전투 포트에 둘 다 적용할 수 있습니다.
Windows 방화벽에서도 Node 서버와 게임 실행 파일의 필요한 인바운드 통신을 허용해야 합니다.

게임 시작 후 서버 콘솔에서 다음 형태의 줄을 찾습니다.

```text
[battle-network] host-ready room=1 account=1 observed=127.0.0.1 reportedPort=7777 advertised=203.0.113.10:7777 source=configured
```

여기서 `7777` 역시 예시입니다. 실제 로그에 표시되는 포트를 사용하세요.
이 경우 공유기의 외부 전투 포트 7777을 **방장 PC의 내부 IP:7777**로 포워딩합니다.
방장 PC의 내부 IP가 바뀌지 않도록 공유기의 주소 예약 기능 등을 사용하세요.
포워딩을 처음 추가한 뒤에는 방으로 돌아가 다시 게임을 시작해 테스트합니다.
TCP 연결 검사만으로 UDP 전투 통신까지 정상이라고 판단할 수 없습니다.

공유기의 외부 포트와 방장 내부 포트를 다르게 쓰는 경우에만 다음처럼 `port`를 추가합니다.

```json
"gameHosts": {
    "YourHostLogin": {
        "address": "203.0.113.10",
        "port": 40000
    }
}
```

방장이 7777을 보고했다면 공유기에는 **외부 40000 → 방장 PC 내부 7777**로 설정합니다.
이 옵션은 참가자에게 알릴 포트만 바꿉니다. 게임 클라이언트의 리스닝 포트나 공유기 설정을 바꾸지 않습니다.
게임을 다시 실행할 때 `reportedPort`가 바뀌면 포워딩 대상도 확인해야 합니다. 가능하면 같은 포트를 사용하는 구성을 먼저 시험하세요.

## 서버를 다른 PC로 분리하거나 VPN을 쓰는 경우

- `publicHost`: 로그인/로비 Node 서버에 접속할 주소입니다.
- `gameHosts.<방장아이디>.address`: 다른 참가자가 **방장 게임 PC**에 접속할 주소입니다. 서버 PC의 IP로 무조건 설정하면 안 됩니다.
- 여러 사람이 번갈아 방장이 되면 각 로그인 아이디별로 항목을 추가하고, 각 방장 쪽 포트도 준비해야 합니다.
- 같은 공유기 안의 다른 PC가 공인 IP로 접속할 때는 공유기의 NAT loopback 지원 여부에 따라 접속이 실패할 수 있습니다. 이 버전은 참가자별 LAN/WAN 주소 자동 선택을 하지 않습니다.
- CGNAT/이중 NAT 등으로 외부에서 방장에게 들어오는 경로를 만들 수 없다면 서버만 이동하는 것으로 해결되지 않습니다. 공인 IPv4/상위 공유기 설정을 확보하거나, 모든 참가자 사이에 통신 가능한 VPN IPv4 경로를 구성한 뒤 방장의 VPN 주소를 지정해야 합니다. VPN 사용 자체가 연결 성공을 보장하지는 않습니다.

새 옵션은 허용 목록을 우회하지 않습니다. `whitelistEnabled`를 켰다면 기존 허용 목록의 로그인 아이디/실제 접속 IP 조건도 만족해야 합니다.

## 로그로 실패 단계 찾기

| 로그 | 의미와 확인 사항 |
| --- | --- |
| `start-refused` | 외부 참가자에게 루프백을 전달하게 되는 설정입니다. `gameHosts`를 확인합니다. |
| `host-listen-failed` | 방장 클라이언트의 응답이 실패이거나 포트가 0입니다. 게임 실행 상태, 방화벽, 포트 충돌을 확인합니다. |
| `host-ready` | 방장이 보고한 내부 포트와 참가자에게 알린 IP/포트를 보여줍니다. 외부 도달 가능성을 검사한 결과는 아닙니다. |
| `peer-connect` | 참가자에게 실제 전달한 방장 주소입니다. 공인 IP/전투 포워딩 대상과 비교합니다. |
| `peer-result ... result=0x...` | 참가자의 응답입니다. 0이 아니면 실패 응답이며 추가 성공 응답을 보내지 않습니다. 정확한 오류 코드 뜻은 아직 확인되지 않았습니다. |
| `peer-leave` | 클라이언트가 전투 종료/복귀 요청을 보냈습니다. 이 패킷만으로 자발적 퇴장과 연결 실패를 구분하지 못합니다. |

같은 맵과 같은 클라이언트 버전으로, 서로 다른 인터넷 회선의 두 PC에서 PVE와 PVP를 각각 시험하세요.
계속 실패하면 게임 시작부터 복귀까지의 `[battle-network]` 로그와 클라이언트 로그를 확인합니다.
로그를 공개할 때는 실제 IP와 계정 등 개인 정보를 가리세요.

## 검증 범위

자동 테스트는 동일 PC/내부망 방장의 외부 주소 전달, 분리 서버의 주소 구분, 외부 포트 변환, 잘못된 포트/설정, PVE/PVP 패킷 및 참가자 실패 응답 처리를 확인합니다.
실제 해외 사용자와의 접속, 공유기·방화벽, 지연/손실이 있는 회선, 게임 전체 플레이는 이 환경에서 검증하지 않았습니다.
이 변경은 주소 전달과 실패 진단을 수정하며, 자동 포트 개방·NAT 우회·전투 중계 서버를 구현하지 않습니다.

게임 클라이언트 IP 설정은 원본 [클라이언트 설치 안내](https://github.com/shanzenos/MRO-Server/wiki/Game-Client-Setup-Tutorial)도 참고하세요.
