# 게임 내부 회원가입 — 검증용 패치

이 패치는 기존 로그인창의 ID/PASSWORD 입력칸을 사용합니다. `Register`는 새 계정을 생성하고 바로 로그인하며, `Login`은 기존 계정의 비밀번호를 검증합니다. 브라우저나 외부 가입 페이지를 열지 않습니다. 별도의 가입 팝업이나 비밀번호 확인 입력칸을 추가한 버전은 아닙니다.

## 현재 검증 상태

- 서버 신규 인증 테스트 7개 통과: 패킷 해석, 비밀번호 해시, 잘못된 비밀번호, 기존 계정 보호, 중복 가입, 요청 제한, 계정/비밀번호/초기 아이템 트랜잭션.
- 기존 서버 테스트 21개와 방/전투/화이트리스트 회귀 스크립트 6개 통과.
- 클라이언트 패키지의 12,096개 export를 비교해 로그인 ButtonClick 함수만 변경됨을 확인.
- 별도의 바이트코드 디코더로 분기 위치, context skip 길이 및 함수 VM 길이 144를 확인.
- 실제 MySQL에서 임시 계정 가입, 초기 아이템 생성, 중복 가입/잘못된 비밀번호 거절, 정상 인증을 확인했습니다. 테스트 계정을 제거한 뒤 기존 계정·아이템·포인트가 보존됨을 확인했습니다. 실제 게임 UI에서 가입부터 재접속까지의 검증은 별도로 필요합니다.

## 적용 전

게임과 서버를 종료하세요. 기존 서버 폴더와 클라이언트 `data/MUD/ZGameMainMenu.tzp`를 백업하세요. 운영 DB도 기존 방식으로 백업하세요.

이 배포본은 test2의 9d2f93e 기반 변경 파일 묶음입니다. 그 이후 별도로 수정한 서버가 있다면 덮어쓰기 전에 비교해야 합니다. 실제 실행 중인 서버 폴더에 적용해야 합니다.

## 서버 적용

압축의 `server` 폴더 **내용물**을 기존 서버 최상위 폴더에 덮어씁니다. `config/server.json`, `database/config.json`, Cache.Bin, 기존 DB는 포함하거나 대체하지 않습니다.

서버 폴더에서 다음을 실행합니다.

```powershell
npm run auth:migrate
```

이 명령은 `account_credentials` 테이블만 추가합니다. 기존 계정, 포인트, 아이템을 삭제하지 않습니다. `metalrageserver.sql`을 다시 실행하지 마세요.

기존 계정은 비밀번호가 없으므로 관리자 설정이 필요합니다. 예를 들어 기존 ID가 Player1이면:

```powershell
node auth/manage.js set-password Player1
```

터미널에서 새 비밀번호를 두 번 입력합니다. 입력은 화면에 표시되지 않으며 명령행 인자로 비밀번호를 전달하지 않습니다. 관리자 설정에서는 기존 클라이언트와 호환되도록 영문/숫자 8~16자를 사용합니다. 다른 기존 계정도 같은 방식으로 설정해야 합니다. 회원가입 버튼으로 기존 ID를 입력해도 계정이나 비밀번호를 덮어쓰지 않습니다.

설정 후 `npm start` 또는 기존 서버 실행 방법으로 시작합니다. 인증 테이블이 없으면 서버가 시작되지 않습니다.

## 클라이언트 적용

압축의 `client/data/MUD/ZGameMainMenu.tzp`를 실제 실행하는 클라이언트의 같은 위치로 복사합니다.

제공받은 클라이언트 기준 대상:

```text
C:/Games/MetalRage Online/data/MUD/ZGameMainMenu.tzp
```

서버 쪽 `static/gamefiles`에 넣는 파일이 아닙니다. 다른 PC 사용자에게도 같은 클라이언트 패치가 필요합니다. 패치하지 않은 클라이언트도 비밀번호 로그인은 가능하지만 Register 버튼은 기존 사이트를 엽니다.

지원하는 원본 파일 SHA-256:

```text
0b7862a1a58a08c8b9e6b71de6b22d162993094b61bf70853398e16e01b0a6f1
```

패치 파일 SHA-256:

```text
8addbf14bd002936ac7d73776bf8906e556f6847972d1e8c31e1776edfa20a5e
```

다른 클라이언트 버전에는 적용하지 마세요. 원본과 패치 파일 해시는 `Get-FileHash -Algorithm SHA256`으로 확인할 수 있습니다.

## 게임에서 확인할 순서

1. 기존에 없는 테스트 ID(영문/숫자 3~24자)와 테스트용 비밀번호(영문/숫자 8~16자 권장)를 입력하고 Register를 클릭합니다.
2. 브라우저가 열리지 않고 로비로 들어오는지, 서버에 `[account-auth] registered account=...`가 찍히는지 확인합니다.
3. 게임을 종료한 뒤 같은 ID/비밀번호로 Login합니다. `[account-auth] authenticated account=...`를 확인합니다.
4. 틀린 비밀번호 및 같은 ID의 중복 Register가 거절되는지 확인합니다. 실패 메시지는 현재 클라이언트의 일반 로그인 오류 표시를 사용합니다.
5. 아이템을 구매하고 재접속해 보유 아이템과 잔액이 유지되는지 확인합니다.
6. 관리자 비밀번호를 지정한 기존 계정으로 접속해 기존 아이템이 유지되는지 확인합니다.

IP당 로그인/가입 시도는 1분에 10회까지입니다. 초과하면 1분 후 다시 시도하세요. 화이트리스트를 켜 둔 서버는 가입 ID도 허용 목록에 있어야 합니다.

## 인증 구현 범위

원본 ZNetwork.dll은 비밀번호를 MD5 32자리 문자열로 보내며, 서버는 이 값을 개별 salt를 사용하는 scrypt로 다시 해시해 저장합니다. DB에 평문 비밀번호나 원본 MD5 값을 저장하지 않습니다. 신규 계정과 인증 정보 및 초기 아이템은 같은 트랜잭션에 저장됩니다. 이전 ID 자동 가입 경로와 인증 전 캐릭터 생성 경로는 차단했습니다.

기존 게임 전송 프로토콜 자체는 TLS가 아니며 MD5 값은 재전송 공격에 사용될 수 있습니다. 따라서 이 패치를 현대적인 보안 인증 체계가 완성된 것으로 간주할 수 없습니다. 실제 서비스 비밀번호를 재사용하지 마세요. 클라이언트는 해시만 보내므로 서버가 원래 비밀번호 길이를 검사할 수 없으며, 신규 가입에는 빈 비밀번호의 해시만 별도로 거절합니다.

## 복구

게임과 서버를 종료하고 백업한 클라이언트 메뉴 파일 및 서버 파일을 복원합니다. 추가한 account_credentials 테이블은 기존 서버가 참조하지 않으므로 삭제하지 않아도 됩니다. 복구 시 기존 서버의 비밀번호 미검증 동작도 돌아온다는 점을 유의하세요.

## 재현용 자료

`tools/client-registration`에는 지원 원본 해시를 확인한 뒤 새 파일을 생성하는 Python 패치 생성기와 독립 바이트코드 검사기가 있습니다. 기존 원본을 수정하지 않습니다. 생성기는 별도 실행 인자로 data 폴더, keys.bin, 출력 폴더를 받습니다. 이미 생성된 패치를 적용하는 데 Python 설치는 필요하지 않습니다.

## 저장소에서 클라이언트 패치 재생성

게임 파일은 저장소에 포함하지 않습니다. 지원 버전의 원본 클라이언트를 준비하고 다음을 실행합니다. Python 표준 라이브러리만 사용하며 게임을 실행하지 않습니다.

```powershell
python tools/client-registration/build_registration_patch.py "C:/Games/MetalRage Online/data" static/gamefiles/keys.bin tools/client-registration/out
python tools/client-registration/verify_bytecode.py tools/client-registration/out/original-menu.unr tools/client-registration/out/patched-menu.unr
```

생성된 ZGameMainMenu.tzp를 원본 백업 후 클라이언트 data/MUD에 적용합니다.
